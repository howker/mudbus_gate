# M4 — Подтверждение на живой Энергосфере (дополнение к M3_DISCOVERY_FINDINGS)

Статус: **M4 подтверждён на живой ПК «Энергосфера» 7.1.** Дата прогона: 19.07.2026. Тестовая запись УСПД «TEST», тип АКРОН-01-1, связь Raw TCP, `127.0.0.1:15021` (боевой carrier запущен на самом сервере ЭС по RDP, без сетевого доступа наружу).

## Метод

- Собран `mbgw.exe` тулчейном Go 1.20.14 (совместимость с Server 2008 R2, см. решение в рабочей переписке от 16.07.2026).
- База наполнена инструментом `tools/seedakron`: паспорт прибора (serial 12345, тип 0x00, версия 3.7), текущие (V/Q/наработка), 200 часовых архивных записей (~8.3 суток вглубь от текущего часа) — с запасом под окно долга ЭС, выставленное оператором на 7 суток (168 ч).
- Запущен боевой carrier: `mbgw.exe northbound --serve-akron --listen 127.0.0.1:15021 --db akron_smoke.db --device acron_1`.
- Обмен зафиксирован в `akron_live.jsonl` (аудит-лог carrier'а, формат идентичен discovery-логу M3).

## Результат: дозабор долга прошёл штатно

При первом подключении тестового УСПД зафиксирован полный, безошибочный дозабор архива вглубь:

| Запрос (i, n) | Результат |
| :-- | :-- |
| i=1, n=1 | 1 запись (вершина, текущий час) |
| i=135, n=28 | 28 записей |
| i=107, n=28 | 28 записей |
| i=79, n=28 | 28 записей |
| i=51, n=28 | 28 записей |
| i=23, n=28 | 28 записей |
| i=1, n=22 | 22 записи (снова вершина — цикл дозабора завершён) |

Итого 135 часовых записей дозабрано одним проходом, без единого повтора запроса и без единого «нет данных» (`68 00`) — ЭС последовательно уменьшала индекс `i` строго на размер порции (28), что подтверждает findings §5 («запрашивает от вершины вглубь, боевой МШ отдаёт n строк начиная с индекса i»).

**Важное уточнение к findings §4 (ранний вывод по зацикливанию):** при первом прогоне (база содержала только 48 часовок) ЭС зациклилась на `i=135, n=28`, повторяя один и тот же запрос каждые ~30 с и получая `68 00`. Изначально это было ошибочно заподозрено как проблема протокола («драйверу нужен специальный маркер пустой ячейки», по аналогии с конвенцией ИВК-ТЭР — пустая запись из нулей — и ТСРВ-024 — маркер времени 0x00000000/0xFFFFFFFF). **Гипотеза не подтвердилась и была отвергнута**: как только глубина seed-базы (200 записей) перекрыла реальный долг ЭС (135 часов), дозабор прошёл гладко без каких-либо специальных маркеров. Корень был тривиален — недостаточная глубина тестовых данных, а не проблема протокола.

**Открытый вопрос на будущее** (не блокирует M4, но стоит держать в уме для боевого Акрона с неполной историей): если у реального, только что подключённого прибора собственный кольцевой буфер физически не содержит запрошенной глубины (устройство только введено в эксплуатацию), поведение ЭС на границе реальных данных прибора не проверялось — потому что в этом прогоне граница была искусственной (глубина seed-базы), а не границей истории самого устройства. Если это станет актуальным — проверить на живом Акроне.

## Критерий успеха (Консоль администратора ЭС)

Панель «Состояние опроса TEST», строка «Основные интервалы» (= ОИ, часовой архив):
- Последние данные: `19.07.2026 11:00:00`
- Отставание: `54 мин`

Это штатный технологический лаг (час 11:00–12:00 на момент снятия скриншота ещё не завершился — последняя закрытая запись естественным образом за 10:00), а не растущий долг. До дозабора отставание было на порядки больше (135+ часов). Критерий DoD M4 №3 («ОИ долг не растёт») — **выполнен**.

Каналы «Показания» и «Текущие значения» обновлялись без отставания на протяжении всего прогона. Канал «События» показывал отставание ~1 сутки — ожидаемо: команда 106 (журнал включений) намеренно не реализована («записей нет», `6a 00`), журналы вне MVP по `MVP_PLAN_akron.md` §7.

## Итог

Сквозной канал **Акрон (симулятор/seed-данные) → МШ → Энергосфера** подтверждён на живой продуктивной системе: текущие значения читаются, часовой архив (ОИ) дозабирается полностью и без потерь, «ОИ долг» не растёт. MVP по Акрону закрыт. Модель B (device-side дозабор архива) подтверждена как рабочая архитектура для northbound.
