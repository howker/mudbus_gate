========================================================================
 MBGW — УСТАНОВКА И ЭКСПЛУАТАЦИЯ НА СЕРВЕРЕ
========================================================================
Актуально на 2026-08-31. Все команды — PowerShell, от имени
администратора, если не указано иное.


------------------------------------------------------------------------
0. ИЗВЕСТНАЯ ПРОБЛЕМА — СЛУЖБА WINDOWS СЕЙЧАС НЕНАДЁЖНА
------------------------------------------------------------------------

ВАЖНО, прочитайте перед тем, как выбирать способ запуска.

Обнаружено 2026-08-31: после запуска через "sc start mbgw_service"
диспетчер служб Windows показывает STATE: RUNNING, но реальная работа
(опрос приборов, сбор архива, запись лога) иногда МОЛЧА ОСТАНАВЛИВАЕТСЯ
вскоре после старта — служба формально "работает", а по факту ничего
не делает. Причина пока не найдена. Подтверждено дважды подряд, с
разными PID.

ДО ИСПРАВЛЕНИЯ ЭТОЙ ПРОБЛЕМЫ:

  РЕКОМЕНДУЕТСЯ запускать РУЧНЫМ РЕЖИМОМ (раздел 1.4 ниже), а не через
  "sc start mbgw_service". Ручной режим проверен и работает надёжно.

  Если нужен автозапуск без участия оператора (сервер перезагружается
  без присмотра) — используйте Планировщик заданий Windows вместо
  службы (раздел 1.5) — он запускает обычный процесс, тем же путём,
  что и ручной режим, но БЕЗ протокола диспетчера служб, где, судя по
  всему, и кроется проблема.

  Служба (install-service/sc start) не удалена и не сломана
  безвозвратно — ей можно пользоваться, особенно для быстрой проверки
  "заработало ли вообще" — но ПОСЛЕ запуска через службу обязательно
  сверьтесь с хвостом лога (раздел 2.2), что туда реально идут свежие
  записи, а не только смотрите на "RUNNING" в sc query — это поле
  сейчас может обманывать.


------------------------------------------------------------------------
1. ПЕРВОНАЧАЛЬНАЯ УСТАНОВКА (сервер "с нуля")
------------------------------------------------------------------------

1.1. Что нужно заранее
-----------------------
  - Windows Server (проверено на 2008 R2, но должно работать и на
    более новых версиях).
  - Собранный mbgw.exe (сборка через
    "go1.20.14 build -mod=vendor -o bin/mbgw.exe ./cmd/mbgw" на машине
    разработки, GOOS=windows GOARCH=amd64).
  - Права администратора на сервере.

1.2. Разместить файл
----------------------
Создайте отдельную папку — не кладите mbgw.exe прямо в C:\. Каждый
файл, который создаёт процесс (база данных, лог, файл с адресом
веб-интерфейса), появляется РЯДОМ с exe.

    New-Item -ItemType Directory -Path C:\mbgw -Force
    Copy-Item путь\до\собранного\mbgw.exe C:\mbgw\mbgw.exe

1.3. Первый запуск — ВРУЧНУЮ (см. раздел 0 про службу)
-----------------------------------------------------------
    cd C:\mbgw
    .\mbgw.exe server

Оставьте это окно консоли ОТКРЫТЫМ — по нему сразу видно, что процесс
реально делает (строки регистрации приборов, сбора архива и т.д.
побегут прямо на экране). Если что-то не так — сразу видно причину, а
не приходится гадать по отсутствию данных потом.

1.4. Ручной режим — подробнее
----------------------------------
Это ПРОВЕРЕННЫЙ, надёжный способ запуска (см. раздел 0). Открываете
консоль, запускаете, оставляете окно открытым:

    cd C:\mbgw
    .\mbgw.exe server

Остановка — Ctrl+C в этом же окне, дождитесь строки
"=== получен сигнал завершения (Ctrl+C). остановка... ===".

Минус ручного режима: если сервер перезагрузится (например, планово
или из-за сбоя питания), процесс не поднимется сам — нужно, чтобы
кто-то вручную зашёл и запустил заново, либо настроить автозапуск
через Планировщик заданий (следующий раздел).

1.5. Автозапуск без службы — через Планировщик заданий Windows
--------------------------------------------------------------------
Пока проблема из раздела 0 не исправлена, это способ получить
автозапуск при перезагрузке БЕЗ использования сломанного протокола
службы — Планировщик просто запускает обычный процесс, тем же путём,
что и ручной режим.

Создать задание (один раз, от имени администратора):

    schtasks /create /tn "mbgw" /tr "C:\mbgw\mbgw.exe server" /sc onstart /ru SYSTEM /rl highest

Проверить, что задание создано:

    schtasks /query /tn "mbgw"

Запустить прямо сейчас, не дожидаясь перезагрузки (для проверки):

    schtasks /run /tn "mbgw"

Остановить (Планировщик не умеет "мягко" останавливать — только
завершить процесс, как Stop-Process):

    Get-Process mbgw | Stop-Process -Force

Удалить задание совсем:

    schtasks /delete /tn "mbgw" /f

ВАЖНО: как и с ручным режимом, после любого запуска через Планировщик
проверяйте хвост лога (раздел 2.2), что видите свежие записи — сам
факт "процесс запущен" ещё не значит "процесс реально работает" (та же
осторожность, что и со службой, см. раздел 0 — хотя проблема отслежена
именно за протоколом службы, лишняя проверка не помешает).

1.6. Открыть веб-интерфейс и настроить приборы
-------------------------------------------------
Адрес всегда записан в mbgw_web_address.txt рядом с exe:

    Get-Content C:\mbgw\mbgw_web_address.txt

Обычно это http://127.0.0.1:8080/admin (порт может быть другим, если
8080 был занят — сервер сам подбирает свободный, смотрите файл выше).

На вкладке "Приборы" добавьте каждый прибор (ВКМ-360 или Akron) —
адрес подключения, тип, при необходимости используйте кнопку
"Проверить прибор" перед сохранением.

На вкладке "Точки ЭС" — ОБЯЗАТЕЛЬНО для КАЖДОГО прибора с прямой
записью в ЭС (сейчас это ОБА типа — и ВКМ, и Akron, см. раздел 3
ниже) настройте, в какие точки (поле ID_PP) базы Энергосферы и с каким
коэффициентом отправлять данные. Без этого шага прибор не отправит в
ЭС вообще ничего — молча, без ошибок, просто нечего отправлять, раз
неизвестно куда.

На вкладке "Подключение к ЭС" — параметры подключения к SQL Server
базе ЭС (сервер, база, логин, пароль), кнопка "Проверить подключение"
перед сохранением.


------------------------------------------------------------------------
2. ПОВСЕДНЕВНАЯ ЭКСПЛУАТАЦИЯ
------------------------------------------------------------------------

2.1. Проверить, что всё работает
------------------------------------
Быстрее всего — вкладка "Главная" в /admin: таблица всех приборов с
отставанием архива, временем следующего опроса и расхождением часов.
Отставание "0" и зелёный цвет — всё в порядке.

2.2. Посмотреть логи — САМАЯ НАДЁЖНАЯ проверка "реально ли работает"
-------------------------------------------------------------------------
Два способа, оба показывают один и тот же лог:

  - Файл — mbgw_server.log рядом с exe. Ротируется автоматически
    (20 МБ на файл, хранится последние 10 архивов).
  - Вкладка "Лог" в /admin — тот же лог, но живьём в браузере,
    обновляется каждые 2 секунды, новые строки СВЕРХУ.

Проверить свежесть, не открывая браузер:

    Get-Content C:\mbgw\mbgw_server.log | Select-Object -Last 20

Если время в последних строках СВЕЖЕЕ (не отстаёт на много минут от
текущего момента) — процесс реально работает. Если строки застыли на
одном времени и не растут — процесс завис (см. раздел 0 про известную
проблему службы; если это ручной режим и тоже завис — сообщите
разработчику, это уже другая, ещё не встречавшаяся проблема).

2.3. Обновить mbgw.exe на новую версию
------------------------------------------
    1. Остановить текущий процесс:
       - ручной режим: Ctrl+C в его консоли
       - через Планировщик: Get-Process mbgw | Stop-Process -Force
       - через службу: C:\Windows\System32\sc.exe stop mbgw_service

    2. Заменить exe:
       Copy-Item путь\до\новой\сборки\mbgw.exe C:\mbgw\mbgw.exe -Force

    3. Запустить снова тем же способом, что использовали до этого.

    4. Проверить хвост лога (раздел 2.2) — свежие записи должны
       появиться в течение минуты-двух после старта.

2.4. Вкладка "Служба" — статус и остановка через веб
--------------------------------------------------------
Работает независимо от того, каким способом запущен процесс (служба,
вручную, через Планировщик) — но раз это МОГ БЫ быть тот же самый
процесс, что описан в разделе 0 (числится "работает", реально нет),
не полагайтесь ТОЛЬКО на эту вкладку — сверяйтесь с логом (2.2).


------------------------------------------------------------------------
3. ТОЧКИ ЭС — ОБЩИЙ МЕХАНИЗМ ДЛЯ ВКМ И AKRON (с 2026-08-31)
------------------------------------------------------------------------

ИЗМЕНЕНО 2026-08-31: раньше ВКМ и Akron доставляли данные в ЭС СОВСЕМ
разными путями:

  - ВКМ — прямая запись в базу ЭС (таблица Mains, потом переименовано
    в PointMains) — то, что и сейчас.
  - Akron — эмуляция физического прибора: ЭС САМА подключалась к mbgw
    через свой драйвер АКРОН-01-1 и сама решала, в какую точку класть
    данные, на основе собственных настроек ЭС. Никакого сопоставления
    "прибор -> точка" в mbgw для Akron не было и не требовалось.

ТЕПЕРЬ оба типа приборов идут ОДНИМ путём — прямой записью в таблицу
PointMains (поле ID_PP), той же самой, что и ВКМ. Старый способ для
Akron (эмуляция прибора) отключён (код остался в проекте
закомментированным, на случай если понадобится вернуться).

ЧТО ЭТО ЗНАЧИТ НА ПРАКТИКЕ: если у вас уже был настроенный, работающий
прибор Akron ДО этого обновления — после обновления его данные
ПЕРЕСТАНУТ идти в ЭС, пока вы явно не зайдёте на вкладку "Точки ЭС" и
не укажете для него ID_PP (реальный номер точки в ЭС, узнать у
администраторов ЭС, mbgw его не знает и не может подобрать сам). У
Akron нужна ровно одна точка — для объёма ("V"). Множитель обычно
оставляют 1 (объём и так уже в м³), меняйте только если в ЭС нужны
другие единицы.

Таблица PointMains в самой ЭС имеет другие названия колонок, чем старая
Mains:

    Старая Mains          Новая PointMains
    ID_Channel        ->  ID_PP
    MeasureDate       ->  DT
    Value             ->  Val
    State             ->  State (без изменений)

Если когда-нибудь будет пересмотрена структура PointMains в самой ЭС —
свериться напрямую через SSMS:

    SELECT COLUMN_NAME, DATA_TYPE, IS_NULLABLE
    FROM INFORMATION_SCHEMA.COLUMNS
    WHERE TABLE_SCHEMA = 'dbo' AND TABLE_NAME = 'PointMains'
    ORDER BY ORDINAL_POSITION;

4. ПРИНУДИТЕЛЬНЫЙ ПЕРЕОПРОС И ПЕРЕСИНХРОНИЗАЦИЯ С ЭС
------------------------------------------------------------------------

Отдельные, редкие, явно запрашиваемые оператором действия:

  - "Принудительный переопрос" (вкладка "Приборы", либо "Архив") —
    пересобирает архив за указанный период заново с прибора и
    перезаписывает НАШУ локальную базу.

  - "Принудительная пересинхронизация с ЭС" (вкладка "Подключение к
    ЭС") — перезаписывает уже отправленные в базу ЭС точки заново
    посчитанными значениями (по текущим настройкам множителя точки).
    Работает для ОБОИХ типов приборов (с 2026-08-31). Обычная
    синхронизация (и кнопка "Синхронизировать сейчас" на "Главной")
    только добавляет новое и никогда не трогает то, что уже есть в
    ЭС — если нужно ИСПРАВИТЬ уже отправленное, нужна именно эта,
    отдельная операция.


------------------------------------------------------------------------
5. ДИАГНОСТИКА ТИПИЧНЫХ ПРОБЛЕМ
------------------------------------------------------------------------

5.1. "Ничего не вывелось" после команды sc ...
--------------------------------------------------
"sc" в PowerShell по умолчанию — АЛИАС команды Set-Content (запись в
файл), а НЕ вызов настоящего sc.exe! Всегда используйте полный путь:

    C:\Windows\System32\sc.exe start mbgw_service
    C:\Windows\System32\sc.exe stop mbgw_service
    C:\Windows\System32\sc.exe query mbgw_service

Проверьте, не появился ли в папке лишний файл с именем команды (start,
stop, query) — если да, это подтверждает, что сработал алиас, а не
настоящий sc.exe:

    Get-ChildItem C:\mbgw

5.2. Служба показывает RUNNING, но данные не собираются
-------------------------------------------------------------
См. раздел 0 — известная, пока не исправленная проблема. Переходите на
ручной режим (раздел 1.4) или Планировщик заданий (раздел 1.5).

5.3. "mbgw.exe уже запущен" при попытке старта
---------------------------------------------------
Это защита от двойного запуска сработала штатно — где-то уже работает
другой экземпляр (возможно, в другом окне/через другой способ
запуска). Проверьте:

    Get-Process mbgw -ErrorAction SilentlyContinue

Остановите лишний экземпляр, прежде чем запускать заново — если
экземпляров окажется два одновременно, оба начнут опрашивать одни и те
же приборы параллельно, мешая друг другу, и одновременно писать в одну
базу и один файл лога.

5.4. Двойной клик по mbgw.exe ничего не делает
---------------------------------------------------
Ожидаемо — mbgw.exe без аргументов просто печатает справку и сразу
завершается. Двойной клик не запускает сервер. Правильный способ —
раздел 1.3 (ручной запуск из консоли) или 1.5 (автозапуск через
Планировщик).

5.5. Не открывается /admin
-------------------------------
Проверьте реальный адрес:

    Get-Content C:\mbgw\mbgw_web_address.txt

Если и это не помогло — посмотрите хвост лога на ошибки старта:

    Get-Content C:\mbgw\mbgw_server.log | Select-Object -Last 50

5.6. После обновления Akron перестал отправлять данные в ЭС
-------------------------------------------------------------------
Ожидаемо, если это первый запуск после обновления 2026-08-31 — см.
раздел 3. Зайдите на вкладку "Точки ЭС", выберите прибор Akron,
укажите ID_PP для объёма.


------------------------------------------------------------------------
6. СТРУКТУРА ФАЙЛОВ РЯДОМ С MBGW.EXE
------------------------------------------------------------------------

  mbgw_server.db (+ -shm, -wal)
      Локальная база (SQLite, режим WAL) — приборы, настройки,
      собранный архив

  mbgw_server.log
      Лог работы, с автоматической ротацией (20 МБ x 10 архивов)

  mbgw_web_address.txt
      Актуальный адрес веб-интерфейса

  <device_id>_akron_live.jsonl
      Диагностический лог сырого обмена с конкретным Akron-прибором


------------------------------------------------------------------------
7. ШПАРГАЛКА КОМАНД
------------------------------------------------------------------------

Ручной запуск (РЕКОМЕНДУЕТСЯ, см. раздел 0):
    cd C:\mbgw
    .\mbgw.exe server
    (остановка: Ctrl+C в этом же окне)

Автозапуск через Планировщик заданий (обходит проблему службы):
    schtasks /create /tn "mbgw" /tr "C:\mbgw\mbgw.exe server" /sc onstart /ru SYSTEM /rl highest
    schtasks /run /tn "mbgw"
    Get-Process mbgw | Stop-Process -Force   (остановка)
    schtasks /delete /tn "mbgw" /f            (удалить совсем)

Служба Windows (сейчас ненадёжна, см. раздел 0):
    cd C:\mbgw
    .\mbgw.exe install-service --port 8080
    C:\Windows\System32\sc.exe start mbgw_service
    C:\Windows\System32\sc.exe stop mbgw_service
    C:\Windows\System32\sc.exe query mbgw_service

Обновление exe:
    (остановить любым используемым способом)
    Copy-Item новый_mbgw.exe C:\mbgw\mbgw.exe -Force
    (запустить тем же способом заново)

Адрес веб-интерфейса:
    Get-Content C:\mbgw\mbgw_web_address.txt

Хвост лога (главная проверка "реально ли работает"):
    Get-Content C:\mbgw\mbgw_server.log | Select-Object -Last 20

Сверка контрольной суммы после копирования нового exe:
    certutil -hashfile C:\mbgw\mbgw.exe SHA256
