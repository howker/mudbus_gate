# M3 — Результаты разведки: протокол опроса Акрона Энергосферой

Статус: **разведка завершена.** Документ фиксирует протокол, снятый с живой ПК «Энергосфера» 7.1 через raw-discovery (МШ прикидывался Акроном на изолированном порту 127.0.0.1:15020). Это первичный источник — в документации производителя Акрона этих деталей нет. Все выводы подтверждены реальным обменом, а не догадками.

## 1. Транспорт и кадрирование
- Энергосфера опрашивает Акрон через тип УСПД **«АКРОН-01-1»**, тип связи **Raw TCP** (Энергосфера — клиент, подключается к порту прибора/шлюза).
- На проводе — **сырые Modbus RTU кадры**: `адрес(1) + PDU + CRC16`, **без MBAP-заголовка**. Не Modbus TCP.
- Порядок байт числовых полей — **little-endian** (согласуется с профилем Акрона `word_order_32: "3210"`).
- Многобайтное время — **BCD**.

## 2. Полная последовательность опроса (один цикл)
Снята из живого лога. Между шагами Энергосфера выдерживает паузы ~30 сек.

| Шаг | Команда (hex/dec) | Назначение | Запрос (пример) | Что отдаёт МШ |
| :-- | :-- | :-- | :-- | :-- |
| 1 | `65` / **101** | Идентификация | `01 65` | тип(1) + версия ПО BCD(1) + заводской №(4Б LE) |
| 2 | `03` / **3** | Чтение времени прибора | `01 03 0010 0004` | регистры 0x10–0x13 = время BCD |
| 3 | `66` / **102** | Текущие результаты | `01 66` | V,Q,U,Pu,время работы,код неисправности |
| 4 | `68` / **104** | **Часовой архив (ОИ)** | `01 68 0001 01` | строки архива (см. §4) |
| 5 | `6a` / **106** | Журнал включений | `01 6a 01 01` | МШ отдаёт «пусто» (`6a 00`) |
| — | `6e` / **110** | Статус/готовность (недокументир.) | `01 6e` | ответ `6e 01 01` («готов») |

Порядок: 110 (или его аналог) появляется рано и повторяется, пока не получит `6e 01 01`; без этого драйвер не идёт дальше.

## 3. Форматы команд (по байтам, из реального обмена)

### 101 — идентификация
Ответ PDU: `65 06 <тип:1> <версияBCD:1> <заводской№:4Б LE>`. `06` — число байт данных (1+1+4).
Пример ответа: `65 06 00 37 39300000` (тип 0, версия 3.7, серийный 12345).
**Боевой МШ:** заводской № — реальный номер опрашиваемого Акрона.

### 03 — время прибора (регистры 0x10–0x13)
Запрос: `03 0010 0004` (4 регистра). Ответ: 8 байт BCD:
- 0x10: секунда(BCD), минута(BCD)
- 0x11: час(BCD), день_недели
- 0x12: дата(BCD), месяц(BCD)
- 0x13: год-2000(BCD), id_am
**Критично:** должно быть **синхронное реальное время**. При рассинхроне Энергосфера НЕ переходит к архиву (см. §5).

### 102 — текущие результаты
Запрос: `66` (без параметров). Ответ: `66 <byteCount> <данные>`, 18 байт данных:
`V(4Б float LE) + Q(4Б float LE) + U(4Б LE) + Pu(1Б) + время работы(4Б LE) + код неисправности(1Б)`.

### 104 — часовой архив (основной интервал ОИ)
Запрос: `68 <i:2Б big-endian> <n:1Б>`, где `i` — стартовый индекс (**i=1 — вершина, самая свежая запись**), `n` — число строк.
Пример: `68 0001 01` — одну строку от вершины.
Ответ: `68 <byteCount> <строки>`. Строка = **9 байт**: `U(4Б LE) + Pu(1Б) + H(BCD) + D(BCD) + M(BCD) + Y(BCD)`.
Значение объёма: `U * 10^(Pu-3)`. Пример строки `c3160000 02 16 17 07 26` = 582.7 м³, 16:00 17.07.2026.

### 106 — журнал включений/отключений
Запрос: `6a <i:1Б> <n:1Б>`. МШ журнал не ведёт → отдаёт **«записей нет»**: ответ `6a 00`.

### 110 — статус (недокументированная)
Запрос: `6e` (без параметров). Ответ `6e 01 01` — принимается драйвером как «прибор готов/жив».

## 4. ДВА КРИТИЧЕСКИХ УСЛОВИЯ приёма архива (главный вывод разведки)
Экспериментально установлено: Энергосфера закрывает долг по ОИ и принимает архив **только если выполнены оба**:

1. **Время прибора синхронно.** На шаге 03 МШ должен отдавать реальное текущее время. При рассинхроне (в тесте была разница 18 лет из-за фикстуры 2008 г.) драйвер зацикливается на чтении времени и НЕ шлёт запрос архива 104.

2. **Метка времени архивной строки попадает в запрашиваемый период.** Энергосфера отбрасывает архивные записи, чья дата вне окна долга. В тесте: пока строка 104 имела дату 05.03.2008, долг ОИ (7 суток, июль 2026) **не закрывался**; как только отдали строку со свежей датой (17.07.2026) — **долг закрылся, ОИ приняты**.

Это же — вероятная причина, по которой архивы с реального Акрона ранее «не шли»: нарушалось одно из двух условий (рассинхрон часов прибора или некорректные метки в архиве).

## 5. Механика запроса архива
- Энергосфера шлёт 104 **по долгу/расписанию ОИ**, а не постоянно. Нет долга — нет запроса 104.
- При долге запрашивает от вершины (i=1) вглубь. Точное поведение перебора индексов при большом долге (одним `n>1` или серией по одной) не критично: боевой МШ отдаёт `n` строк из БД начиная с индекса `i`, сколько запрошено — формат один, число строк переменное.

## 6. Что это даёт для боевого M4
Полная спецификация northbound-Акрона (МШ прикидывается Акроном перед Энергосферой), где вместо фиктивных заглушек — реальные данные из локальной БД МШ:
- **101** → реальный заводской номер опрашиваемого прибора;
- **03** → синхронное время (МШ ведёт время; отдельно — коррекция часов самого Акrona вниз при рассинхроне сверх порога, это подсистема синхронизации времени);
- **102** → реальные текущие из БД;
- **104** → **реальные часовки из БД** (собранные стратегией `akron_archive`), маппинг «индекс i от вершины → запись БД», с реальными метками времени;
- **106** → «пусто» (`6a 00`), журнал МШ не ведёт;
- **110** → `6e 01 01`.

Условия §4 — обязательная часть контракта M4: без синхронного времени и корректных меток архив наверх работать не будет.
