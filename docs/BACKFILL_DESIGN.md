# Дизайн: дозабор архива как штатная часть цикла поллера

_Согласовать перед реализацией. Закрывает пункты 3 и 4 из PROJECT_HANDOFF.md
(«дозабор в обычный цикл» + «max_archive_rows_per_request как поле профиля»)._

## Модель работы (согласовано с заказчиком)

mbgw — **не** SCADA реального времени, а **сборщик архивов**. Штатный сценарий:
сервер мог простоять час, сутки или 20 дней; при включении сервис должен
вычитать из кольцевого буфера прибора **всё, чего у него ещё нет**, вглубь
до настроенного лимита — и продолжать латать дыры в дальнейшем, а не только
забирать «свежий час раз в час».

## Ключевой факт про чтение архива Акрона (из akronbackfill)

Команда 104 читается **по индексам строк**, не по датам:
- индекс 0 = самый свежий завершённый час, дальше вглубь (1, 2, …);
- за один запрос — не больше `page_size` строк (для fw 6.6 реально 27,
  хотя документация обещает 31; 28+ отклоняется исключением 0xFC);
- читаем страницами, пока страница не вернёт пусто/ошибку — это и есть
  «архив прибора закончился» (или мы упёрлись в лимит глубины).

## Поведение дозабора

### Глубина (сколько грести назад)

- **Лимит в конфиге НЕ задан → вариант «В»:** грести до строки, которая
  уже есть в нашей SQLite (добираем только отсутствующее), с жёстким
  предохранителем — не глубже физического максимума буфера прибора.
- **Лимит в конфиге задан → вариант «Б»:** грести не глубже указанного
  числа часов/суток, даже если в приборе есть более старые строки.
- Предохранитель по умолчанию (если база пуста и лимит не задан): не
  грести бесконечно — остановиться, когда прибор сам вернёт пустую
  страницу. Экспериментально буфер Акрона ≈ **27 суток** (~648 часов);
  это НЕ хардкодим как предел — это поле профиля с запасом, реальный конец
  определяется пустой страницей от прибора.

### Когда

1. **При старте процесса** — один полный проход дозабора.
2. **Периодически** — каждый архивный тик проверять целостность за
   разумное недавнее окно (напр. последние N суток из конфига) и латать
   обнаруженные дыры. Дыра может появиться и без полной остановки — от
   одного сбойного часа.

### Пустой / обнулённый прибор (защита)

Новый прибор только поставили на объект, архив пуст/обнулён:
- первая же страница возвращает 0 строк или строки с filler-датами
  (0x00/0xFF), которые `akronRowTime` уже отбраковывает → дозабор
  завершается штатно, «добирать нечего», без ошибок и без записи мусора;
- никаких «нулевых часовок» в базу не пишем: строка без валидной BCD-даты
  **или** без поля volume пропускается (уже так в persistAkronHourly);
- если все страницы пусты — просто лог «архив прибора пуст» и выход, поллер
  продолжает штатно (текущие значения читаются независимо от архива).

## Новые поля профиля/конфига (вместо констант и флагов)

В профиль устройства (`profiles/acron-01.yaml`, секция archive):
```yaml
archives:
  - id: hourly
    strategy: akron_archive
    max_rows_per_request: 27   # было: константа/флаг --page-size (fw 6.6 = 27)
    buffer_depth_hours: 648    # физический предел буфера прибора (~27 сут), предохранитель
```

В конфиг устройства (`config.akron_real.yaml`, опционально):
```yaml
devices:
  - id: akron_real
    backfill:
      max_depth_hours: 0     # 0/не задано = вариант В (до имеющегося в БД, но не глубже buffer_depth_hours)
                             # >0            = вариант Б (не глубже стольких часов)
      gap_scan_window_hours: 72   # какое недавнее окно проверять на дыры каждый тик
```

Значения по умолчанию сохраняют текущее подтверждённое поведение, если
секции нет: `max_rows_per_request` fallback = 27, `buffer_depth_hours`
fallback = 648, `max_depth_hours` = 0 (вариант В), gap-scan = 72ч.

## Что меняется в коде (план, не финал)

   в `Archive`; распарсить из YAML.
2. `internal/config` — добавить опциональный `Backfill` в `DeviceConfig`.
3. `internal/device` — новый метод `BackfillArchives(ctx, opts)`:
   постраничный цикл по индексам (перенести из akronbackfill), с
   вычислением «докуда грести» по варианту Б/В и предохранителю.
4. `internal/device` — «gap scan»: найти отсутствующие часы в
   `[now-gap_scan_window .. now]` (SQL по существующим ts_hour), добрать
   точечно.
5. `internal/poller` / `cmd/mbgw/{run,serve}.go` — вызвать backfill один
   раз при старте, затем цепляться к архивному тику для gap-scan.
6. `tools/akronbackfill` — оставить как ручной инструмент (не удалять), но
   его цикл теперь общий с device.BackfillArchives (не дублировать логику).
