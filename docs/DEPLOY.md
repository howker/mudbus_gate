# mbgw — установка и эксплуатация на сервере

Актуально на 2026-08-30. Все команды — PowerShell, от имени администратора,
если не указано иное.

---

## 0. Прежде чем начать — важная ловушка PowerShell

`sc` в PowerShell по умолчанию — **алиас** команды `Set-Content` (запись в
файл), а НЕ вызов настоящего `sc.exe` (управление службами Windows)!
Если набрать `sc start mbgw_service`, PowerShell молча создаст файл с
именем `start` вместо запуска службы — без единой ошибки, просто ничего
не произойдёт.

**Всегда используйте полный путь**, когда управляете службой вручную:

```powershell
C:\Windows\System32\sc.exe start mbgw_service
C:\Windows\System32\sc.exe stop mbgw_service
C:\Windows\System32\sc.exe query mbgw_service
```

Проще и надёжнее — управлять службой через веб-интерфейс, вкладка
«Служба» (см. раздел 2.4), туда эта ловушка вообще не относится.

## 1. Первоначальная установка (сервер «с нуля»)

### 1.1. Что нужно заранее

- Windows Server (проверено на 2008 R2, но должно работать и на более
  новых версиях).
- Собранный `mbgw.exe` (см. `README` разработки — сборка через
  `go1.20.14 build -mod=vendor -o bin/mbgw.exe ./cmd/mbgw` на машине
  разработки, `GOOS=windows GOARCH=amd64`).
- Права администратора на сервере — установка службы требует
  повышенных прав.

### 1.2. Разместить файл

Создайте отдельную папку — **не кладите `mbgw.exe` прямо в `C:\`**.
Каждый файл, который создаёт процесс (база данных, лог, файл с адресом
веб-интерфейса), появляется РЯДОМ с exe — если он лежит в `C:\`, эти
файлы засорят корень диска.

```powershell
New-Item -ItemType Directory -Path C:\mbgw -Force
Copy-Item путь\до\собранного\mbgw.exe C:\mbgw\mbgw.exe
```

### 1.3. Установить как службу Windows

Это **рекомендуемый** способ запуска в проде — служба стартует
автоматически при загрузке сервера, не требует держать открытой
консоль, и корректно останавливается штатными средствами Windows.

```powershell
cd C:\mbgw
.\mbgw.exe install-service --port 8080
```

Если порт 8080 когда-либо окажется занят другим процессом — сервер сам
подберёт свободный порт при старте и запишет реальный адрес в
`mbgw_web_address.txt` рядом с exe, ничего вручную чинить не нужно.

### 1.4. Запустить службу первый раз

```powershell
C:\Windows\System32\sc.exe start mbgw_service
C:\Windows\System32\sc.exe query mbgw_service
```

В выводе `query` ищите строку `STATE` — должно быть `RUNNING`. Если
видите ошибку 1053 («служба не ответила на запрос своевременно») —
см. раздел 4.2, но эта проблема уже исправлена в текущей версии
(добавлена настоящая поддержка протокола служб Windows).

### 1.5. Открыть веб-интерфейс и настроить приборы

Адрес всегда записан в `mbgw_web_address.txt` рядом с exe:

```powershell
Get-Content C:\mbgw\mbgw_web_address.txt
```

Обычно это `http://127.0.0.1:8080/admin`. Откройте его в браузере (с
самого сервера, либо с другого компьютера в той же сети, заменив
`127.0.0.1` на реальный IP сервера).

На вкладке **«Приборы»** добавьте каждый прибор (ВКМ-360 или Akron) —
адрес подключения, тип, при необходимости используйте кнопку
«Проверить прибор» перед сохранением.

На вкладке **«Каналы ЭС»** — для приборов ВКМ настройте, в какие
каналы `Mains` базы Энергосферы и с каким коэффициентом отправлять
массу/тепло/температуру/давление.

На вкладке **«Подключение к ЭС»** — параметры подключения к SQL Server
базе ЭС (сервер, база, логин, пароль), кнопка «Проверить подключение»
перед сохранением.

Для приборов Akron, которых ЭС опрашивает сама (через эмуляцию
прибора) — вкладка **«Приём Акрона (ЭС)»**, адрес прослушивания.

## 2. Повседневная эксплуатация

### 2.1. Проверить, что всё работает

Быстрее всего — вкладка **«Главная»** в `/admin`: таблица всех
приборов с отставанием архива, временем следующего опроса и
расхождением часов. Отставание `0` и зелёный цвет — всё в порядке.

### 2.2. Посмотреть логи

Два способа, оба показывают один и тот же лог:

- **Файл** — `mbgw_server.log` рядом с exe. Ротируется автоматически
  (20 МБ на файл, хранится последние 10 архивов) — не растёт
  бесконечно.
- **Вкладка «Лог»** в `/admin` — тот же лог, но живьём в браузере,
  обновляется каждые 2 секунды, новые строки сверху. Есть пауза,
  копирование, сохранение в файл, подсветка ошибок/предупреждений.

### 2.3. Обновить `mbgw.exe` на новую версию

Работающий процесс держит свой exe-файл — Windows не даст его
перезаписать, пока служба не остановлена. Порядок:

```powershell
# 1. Остановить службу
C:\Windows\System32\sc.exe stop mbgw_service

# 2. Убедиться, что реально остановилась (не STOP_PENDING)
C:\Windows\System32\sc.exe query mbgw_service

# 3. Заменить exe
Copy-Item путь\до\новой\сборки\mbgw.exe C:\mbgw\mbgw.exe -Force

# 4. Запустить снова
C:\Windows\System32\sc.exe start mbgw_service
C:\Windows\System32\sc.exe query mbgw_service
```

Тот же результат можно получить, остановив службу через вкладку
«Служба» в `/admin` (см. ниже) вместо шага 1 — это даже удобнее,
не нужно помнить про ловушку с `sc`.

### 2.4. Вкладка «Служба» — статус и остановка через веб

На вкладке видно:
- Запущены ли мы службой Windows или обычным ручным процессом.
- Установлена ли служба, и если да — её текущее состояние
  (работает/остановлена/...).
- Кнопка **«Остановить»** — работает независимо от того, служба это
  или ручной запуск.

Кнопки «Запустить» там **намеренно нет**: страница обслуживается тем
же самым процессом, который пришлось бы запускать — если он уже
остановлен, обслуживать нажатие кнопки просто некому. Запустить снова
— это всегда `sc start mbgw_service`, «Службы Windows» (services.msc),
либо служба сама поднимется при следующей перезагрузке сервера
(автозапуск уже настроен при установке).

### 2.5. Защита от двойного запуска

Встроена автоматически — если попробовать запустить `mbgw.exe server`
вручную, пока служба уже работает (или наоборот) — второй экземпляр
сразу откажется стартовать с понятной ошибкой в консоли/логе, вместо
того чтобы тихо конфликтовать с первым за приборы и порт. Специально
ничего настраивать не нужно.

## 3. Принудительный переопрос и пересинхронизация с ЭС

Отдельные, редкие, явно запрашиваемые оператором действия — не
путать с обычной автоматической работой:

- **«Принудительный переопрос»** (вкладка «Приборы», либо «Архив») —
  пересобирает архив за указанный период заново с прибора и
  перезаписывает НАШУ локальную базу. Полезно после физического
  ремонта прибора/датчика, если раньше приходили искажённые данные.

- **«Принудительная пересинхронизация с ЭС»** (вкладка «Подключение к
  ЭС») — отдельно от переопроса выше: перезаписывает уже отправленные
  в базу ЭС точки заново посчитанными значениями (по текущим
  настройкам множителя канала). Обычная синхронизация (и кнопка
  «Синхронизировать сейчас» на «Главной») только добавляет новое и
  никогда не трогает то, что уже есть в ЭС — если нужно ИСПРАВИТЬ уже
  отправленное (например, после смены множителя канала), нужна именно
  эта, отдельная операция.

## 4. Диагностика типичных проблем

### 4.1. «Ничего не вывелось» после команды `sc ...`

См. раздел 0 — почти наверняка сработал алиас PowerShell вместо
настоящего `sc.exe`. Проверьте, не появился ли в папке лишний файл с
именем команды (`start`, `stop`, `query`):

```powershell
Get-ChildItem C:\mbgw
```

Если да — удалите его и повторите команду с полным путём
`C:\Windows\System32\sc.exe`.

### 4.2. Ошибка 1053 при запуске службы

`[SC] StartService: ошибка: 1053. Служба не ответила на запрос
своевременно.` — в текущей версии `mbgw.exe` эта проблема уже
исправлена (добавлена настоящая поддержка протокола служб Windows,
`golang.org/x/sys/windows/svc`). Если ошибка всё же появилась —
убедитесь, что установлена версия exe **после** 2026-08-30 (проверьте
дату сборки/коммит), и что служба была переустановлена заново после
обновления:

```powershell
C:\Windows\System32\sc.exe delete mbgw_service
.\mbgw.exe install-service --port 8080
C:\Windows\System32\sc.exe start mbgw_service
```

### 4.3. «mbgw.exe уже запущен» при попытке старта

Это защита от двойного запуска сработала штатно (см. 2.5) — где-то
уже работает другой экземпляр. Проверьте:

```powershell
C:\Windows\System32\sc.exe query mbgw_service
Get-Process mbgw -ErrorAction SilentlyContinue
```

Остановите лишний экземпляр (через `/admin` → «Служба», либо `sc
stop`, либо Ctrl+C в его консоли, если запущен вручную), прежде чем
запускать заново.

### 4.4. Двойной клик по `mbgw.exe` ничего не делает

Ожидаемо — `mbgw.exe` без аргументов просто печатает справку и сразу
завершается, окно консоли мелькает и закрывается. Двойной клик не
запускает сервер. Правильный способ — установить как службу (раздел
1.3), тогда сервер стартует сам при каждой загрузке машины без единого
ручного действия.

### 4.5. Не открывается `/admin`

Проверьте реальный адрес (порт мог не совпасть с ожидаемым, если он
был занят):

```powershell
Get-Content C:\mbgw\mbgw_web_address.txt
```

Если и это не помогло — посмотрите хвост лога на ошибки старта:

```powershell
Get-Content C:\mbgw\mbgw_server.log | Select-Object -Last 50
```

(команда `-Tail` недоступна в старых версиях PowerShell — используйте
`Select-Object -Last N`, как выше).

## 5. Структура файлов рядом с `mbgw.exe`

Все файлы появляются автоматически, рядом с exe, независимо от того,
откуда его запустили:

| Файл | Назначение |
|---|---|
| `mbgw_server.db` (+ `-shm`, `-wal`) | Локальная база (SQLite, режим WAL) — приборы, настройки, собранный архив |
| `mbgw_server.log` | Лог работы, с автоматической ротацией (20 МБ × 10 архивов) |
| `mbgw_web_address.txt` | Актуальный адрес веб-интерфейса — сверяйтесь сюда, если порт когда-либо менялся |
| `<device_id>_akron_live.jsonl` | Диагностический лог сырого обмена с конкретным Akron-прибором (по одному на прибор с настроенным northbound) |

## 6. Шпаргалка команд

```powershell
# Установка службы (один раз)
cd C:\mbgw
.\mbgw.exe install-service --port 8080

# Управление службой (ВСЕГДА полный путь к sc.exe!)
C:\Windows\System32\sc.exe start mbgw_service
C:\Windows\System32\sc.exe stop mbgw_service
C:\Windows\System32\sc.exe query mbgw_service
C:\Windows\System32\sc.exe delete mbgw_service   # полное удаление службы

# Обновление exe
C:\Windows\System32\sc.exe stop mbgw_service
Copy-Item новый_mbgw.exe C:\mbgw\mbgw.exe -Force
C:\Windows\System32\sc.exe start mbgw_service

# Адрес веб-интерфейса
Get-Content C:\mbgw\mbgw_web_address.txt

# Хвост лога
Get-Content C:\mbgw\mbgw_server.log | Select-Object -Last 50

# Сверка контрольной суммы после копирования нового exe
certutil -hashfile C:\mbgw\mbgw.exe SHA256
```
