# FINAL_TRD — Окончательное техническое задание «Модбас-Шлюз»

Статус: зафиксировано. Агент реализует по этому документу и не принимает архитектурных решений. Все неоднозначности разрешены здесь или в CONTRACTS.md.

## 1. Назначение
Мультипротокольный профиле-ориентированный сервер сбора данных для АСКУЭ/АИИС КУЭ в изолированной (без интернета) сети. Опрос зоопарка приборов по расписанию, контроль качества, хранение, выдача наверх, резерв, web-администрирование.

## 2. Зафиксированные технические решения (не пересматриваются)
- Ядро: **Go 1.20.x**, `CGO_ENABLED=0`, single static binary `mbgw`.
- Сборка: **offline/vendor-first**, `GOFLAGS=-mod=vendor`, `GOPROXY=off`, `GOTOOLCHAIN=local`.
- Хранилище: **SQLite** (modernc.org/sqlite, чистый Go) по умолчанию; PostgreSQL/TimescaleDB опционально для истории.
- Протокольный слой: **profile-driven Protocol HAL**; прибор описывается профилем (profile.schema.json), не кодом.
- Протоколы: **Modbus** (+ суб-диалект ВЗЛЕТ функции 17/65) и **Меркурий** (свой протокол).
- Web UI: **TypeScript SPA**, вшит через `go:embed` (`web/dist`).
- Платформы: **Windows Server 2012 / 2008 R2** и **Linux** (x86-64). Один тулчейн Go 1.20.x покрывает разработку, цели и кросс-сборку.
- Разработка и тестирование **без реальных приборов** — через симуляторы, testdata и smoke-тесты.

## 3. Границы (MVP / post-MVP / исключено)

### 3.1. Входит в MVP
- Протокол Modbus (функции 03/04/06/16), framing RTU и TCP, CRC16, исключения (вкл. 06 BUSY).
- Суб-диалект ВЗЛЕТ: функции 17 (инфо), 65/0x41 (архивы по индексу/времени).
- Протокол Меркурий: кадр, открытие/закрытие канала, keepalive 240 c, длинные ответы, статусы X0..X5.
- Кодеки: int16, uint16, int32, uint32, float, double, scaled_int, u32+float, long+float, string, asciiz, bitfield, stInfoEvent; порядки байт 0123/3210/1032/2301.
- Профили 4 приборов: ВКМ-360, ИВК-ТЭР, ТСРВ-024, Меркурий (текущие значения + архивы).
- 4 стратегии архивов: mb_request_poll_string, mb_indexed_binary, mb_func65, merkuriy_long_response.
- Сессии: byte order detect + авторизация (ВКМ), уровни доступа (ИВК), канал+пароль+keepalive (Меркурий).
- Каналы: **Modbus TCP, RTU/COM-RS485, TCP-Serial**. Основной/резервный канал на прибор. **Failover канала — входит** (по таймауту/числу ошибок/деградации), failback по умолчанию выключен.
- Планировщик: цикл текущих + окно архивов (дозабор), приоритеты, ручной опрос, отложенный повтор, ограничение нагрузки.
- Хранилище SQLite: конфигурация, текущие, история, архивы, события связи, тревоги, аудит.
- Качество данных: слияние статус-бит прибора + проверок шлюза (диапазон/stale/разрывы).
- Мониторинг: события сеанса, SSE-поток, тревоги.
- REST API (OPENAPI.yaml) + Web UI (оператор): обзор, устройства, каналы, онлайн-опрос, события, тревоги, ручной опрос/тест канала.
- Аренда устройства (lease, локальная): анти-двойной-опрос + сериализация stateful-сессий.

### 3.2. Post-MVP (закладывается интерфейсами, реализуется позже)
- **GSM/модем** и **VPN/IP** каналы (типы заведены в схеме/БД; физическая реализация — позже).
- **Аутентификация/RBAC/TLS/роли (4)** — каркас в MVP отключаемый; полноценно — post-MVP (см. 3.4).
- **i18n/локализация** — все строки UI сразу через каталог; формализация — post-MVP.
- **Горячее резервирование узлов** (active/standby, heartbeat, fencing) — post-MVP.
- **Сервер обновлений и офлайн-пакеты** (распространение профилей/ядра) — post-MVP.
- **Интеграция наружу**: экспорт CSV/JSON/XML — MVP-минимум; gRPC/MQTT/внешняя БД — post-MVP.
- **Мастер нового прибора**: сниффер, полуавтоматическая расшифровка, продуктовый ИИ — post-MVP.
- PostgreSQL/TimescaleDB бэкенд — post-MVP (интерфейс Repo в MVP).

### 3.3. Явно исключено
- Облачные сервисы, телеметрия наружу, любые обращения в интернет в рантайме.
- Тонкие Windows-клиенты, ActiveX/COM/DCOM.
- Автоматическое принятие архитектурных решений ИИ-агентом в рантайме (продуктовый ИИ только предлагает, человек утверждает).
- Запись управляющих воздействий в приборы сверх задокументированных (авторизация/преамбула/запросы архивов).

### 3.4. Безопасность/RBAC/TLS/audit/i18n — статус по MVP
| Возможность | MVP | Примечание |
| :-- | :-- | :-- |
| Аудит изменений (audit_log) | **входит** | таблица и запись на изменения конфигурации |
| Аутентификация (логин/пароль) | каркас | таблицы users/roles есть; включение — флагом |
| RBAC (4 роли) | post-MVP | матрица прав описана, применение — post-MVP |
| TLS web/API | **входит (самоподписанный)** | сервер обязан уметь TLS |
| i18n (русский) | **входит** | все строки UI через каталог ru.json |

## 4. Поддерживаемые приборы и сценарии
| Прибор | Протокол | Текущие | Архивы (стратегия) | Сессия |
| :-- | :-- | :-- | :-- | :-- |

## 5. Поддерживаемые каналы и режимы
- **MVP:** modbus_tcp, rtu_serial (COM/RS-485), tcp_serial. Основной/резервный, failover (вкл.), failback (выкл. по умолчанию), тест канала.
- **Post-MVP:** gsm, vpn.

## 6. Нефункциональные требования (числовые ограничения — обязательны)
- **Платформы:** Windows Server 2012/2008 R2, Linux x86-64. Тулчейн Go 1.20.x.
- **Offline:** сборка и работа без интернета; зависимости в `vendor/`; фронт в `web/dist`; данные тестов в `testdata/`.
- **Память:** базовый процесс ≤ 256 МБ при 200 устройствах (без учёта БД).
- **Подключения:** до **256 устройств** и до **32 каналов** на узел в MVP.
- **Таймауты (по умолчанию, переопределяются в канале/профиле):** ответ Modbus TCP/RTU — 1000 мс; ТСРВ — 1500 мс; Меркурий — 300 мс; межкадровая пауза RTU — по скорости (для 9600: ≥ 4 мс).
- **Повторы:** по умолчанию 3, с экспоненциальным backoff (200/400/800 мс).
- **Очереди:** глубина очереди задач планировщика ≤ **10 000**; при переполнении — отбрасывание по нижнему приоритету с записью события.
- **Размер архивного ответа:** строковый ответ ВКМ — до **64 КБ** на запрос; бинарные записи читаются блоками ≤ **250 регистров** (предел Modbus); Меркурий long-response — **≤ 255 байт** на кадр.
- **Логирование:** структурный JSON-лог; уровни error/warn/info/debug; ротация по размеру (по умолчанию 50 МБ × 5 файлов); без вывода паролей/секретов.
- **Производительность:** один узел обеспечивает опрос 256 устройств с периодом текущих ≥ 5 c при 3 каналах (ориентир, проверяется нагрузочным тестом).
- **Надёжность:** устойчивость к обрывам канала; восстановление сессии; атомарная запись конфигурации; отсутствие двойного опроса одного устройства.

## 7. Доменные сущности
sites, channels, devices, device_profiles, protocol_templates, poll_schedules, readings_current, readings_history, archive_records, comm_events, alarms, audit_log, redundancy_events, update_packages, device_leases, users, roles, permissions, role_permissions, user_roles, web_sessions. ## 8. Критерии приёмки MVP (глобальный DoD)
1. `make ci` проходит офлайн; `make build-legacy` собирает бинарь тулчейном Go 1.20.x.
2. `mbgw run --config testdata/config.mock.yaml` поднимает API (TLS) и не падает.
3. `mbgw simulate <device>` для всех 4 приборов отдаёт ожидаемые ответы (см. MOCK_DATA_SPEC).
4. Поллер читает каждый из 4 mock-приборов (текущие + архив) и пишет в SQLite.
5. REST отдаёт `/status`, `/devices`, `/devices/{id}/readings`, ручной `/poll`; SSE `/monitor/stream` отдаёт события.
6. Web UI на mock-бэкенде показывает устройства, текущие значения, живой лог.
7. Все smoke-тесты из TEST_STRATEGY проходят без реального оборудования.
8. Качество значений учитывает статус-биты прибора (на mock-сценарии с ошибкой датчика).
